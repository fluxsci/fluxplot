## Actual notebook frontend acceptance (N1)

Tested VS Code 1.138.0, QMD Notebook 0.1.0 and Jupyter 2025.9.1 with disposable profiles,
installed extension copies, and a scratch ipykernel. The frontend extensions executed
ordinary notebook cells through their normal kernel controllers; the outputs were not
hand-constructed HTML. Trusted QMD and Jupyter both execute the bundled scripts and
prefer interactive HTML over the alternate PNG.

Both frontends display a branched neuron with three named parts, legend, physical scale
bar and shape slider. Real pointer drag changes azimuth30→18 and elevation20→24; wheel
changes zoom0.9→0.99; the native range control sets shape0.01; Top sets elevation90; Home
restores the authored view. Copy view selects the exact Python dictionary text. The
selected values were applied through the live QMD scratch kernel with `sc.view(**view)`
and `fp.save`; all requested camera and state values match the saved manifest. PNG-only
`sc.show(static=True)` outputs display in both trusted frontends. Clearing outputs
releases every document viewer owner.

A generated HTML page tests four simultaneous outputs (neuron, continuous field,
shape-state and sequence), pointer isolation, keyboard state controls, authored
fractional frame2.5 and Home synchronization. With scripts disabled, all four inline
PNGs remain visible. Independent renderer review repeated that script-free check.

**Trust limitation:** actual untrusted VS Code selects but suppresses the entire mixed
HTML+PNG output; it does not automatically fall back to PNG. A PNG-only persisted output
was verified in untrusted Jupyter. The separate QMD untrusted probe injected saved
kernel outputs into a temporary NotebookDocument and remained blank even for PNG-only
output, so untrusted QMD restoration is inconclusive. The package cannot override
frontend trust policy. Use the frontend's PNG representation selector where available,
or create explicit static outputs before sharing; do not promise automatic fallback.

## Reproducible assets and measured serialization

```sh
uv run --extra mesh python examples/scene3d_demo.py
```

The default scratch folder is `test-results/model3d/demo/plots/`; `--out` selects another
scratch destination. It contains neuron.glb, cortex-states.glb, cortex-pial.glb,
cortex-inflated.glb, continuous-field.glb and cell-sequence.glb with their manifests.
The neuron has soma/axon/dendrites and a scale bar; the cortex has two named states and
a same-topology partner pair; the sequence has eight frames. No downloaded data needed.

A 999698-triangle / 501264-vertex scene measured 262.526 ms construction and 176.595 ms
numpy-only GLB serialization, producing 24027764 bytes (22.9147 MiB). These are CPU
writer measurements, not GPU rendering numbers. Flux owns the separate P0.6 renderer
measurements and end-to-end Figure/Slides gates.

Known visual limit: the PNG fallback uses a face painter, so intersections and
transparent occlusion can differ from the WebGL depth buffer. The PNG is rasterized at
120 dpi while the interactive furniture follows CSS96 dpi, so text appears larger in
the PNG at its natural pixel dimensions; this fallback does not claim pixel parity. Both notebook views use
white paper behind authored ink for dark-theme readability; GLB and Flux export
transparency remain unchanged. Optional simplification can alter categorical boundaries
within parts and can retain more faces than requested when the backend cannot reach
a quota; it warns explicitly. Allocation itself never exceeds the total quota.
